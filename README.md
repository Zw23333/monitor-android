给 [monitor-probe/monitor](https://github.com/monitor-probe/monitor) 写的安卓客户端：显示**主控（hub）自身的信息**和它下面的节点，并带一个主屏小组件。

设计语言是**安卓原生自动取色**：Android 12 及以上整个配色由系统从壁纸推导（Material You / Monet），app 不指定任何品牌色。小组件同样走 `GlanceTheme`，和 app 取同一个色源，所以两者永远不会对"主色"的理解不一致。

## 功能

**主控信息**（首屏第一张卡）

| 分组 | 内容 |
|---|---|
| 概览 | 节点总数 / 在线 / 离线、总上行下行、本月已用流量、计费节点 |
| 版本 | 主控版本、主控最新版、Agent 最新版（登录后可见） |
| 数据库 | 文件大小、WAL、可回收页、保留天数、最早记录、各表行数 |
| 设置 | 公开页开关、保留天数、当前主题、你的来源地址 |

**节点列表** — 每台一张卡：在线状态、系统/虚拟化/架构、CPU / 内存 / 硬盘 / 本月流量四条进度条、上下行速率、TCP 连接数、进程数、运行时长、负载、累计流量、价格与到期时间。点进去是详情页。

**分组** — hub 的 `group` 字段是手工设的、公开的，空即未分组。列表按组分小节显示，上方一排筛选 chip：`全部` / 各组 / `未分组`（后者只在真有未分组节点时出现）。组的顺序**由第一个带该组的节点决定**，不按字母排——这样节点增减时小节不会在读者眼皮底下重新排序。未分组那一节的标题只在**存在具名分组时**才显示，否则一个没人分组的 hub 会顶着一个"未分组"标题。

筛选的编码沿用面板那一套：`all` / `none` / `=` + 组名。前面那个 `=` 是必须的——否则一个真叫 "all" 或 "none" 的分组就没法和这两个关键字区分开。

**延迟监控**（详情页）— 走 hub 的 `/api/nodes/{id}/metrics`，**请求里故意不带 `series`**：hub 会因此用同一次扫描把资源采样和探针延迟一起返回，分两次请求就是扫两遍同一个窗口。

- 每个探针一条曲线：**中位延迟**折线 + 每桶的 **min/max 区间带** + 丢包处画竖线
- 丢包按探针显示（窗口整体 + 每桶），hub 给的是**未取整**的百分比，所以 0.14% 不会被显示成 0%
- 没有应答的桶画成**断线**而不是连过去 —— 那是真实的探测中断
- 窗口可切 1 小时 / 6 小时 / 24 小时 / 7 天（hub 自己会按保留期截断）
- 同一页还有资源历史：CPU、内存、下行、上行四条 sparkline

**小组件** — 主屏上的汇总：`在线数 / 总数`、离线数、总上下行、本月流量、主控版本、更新时间。点一下打开 app，点底部一行强制刷新。

## 省电与生命周期

这是上一版最实打实的问题：轮询跑在 `Application` 的 scope 里，熄屏、切后台、Doze 期间照跑不误 —— 而平台在 Doze 里挂起网络，正是为了让这种轮询停下来。现在的模型是：

| 场景 | 谁在刷新 | 行为 |
|---|---|---|
| 界面在前台 | `MainActivity` 的 `repeatOnLifecycle(STARTED)` | 按用户设的间隔（2–300 秒）轮询 |
| 界面不可见 / 熄屏 | 无人刷新 | 协程随 `onStop` 被取消，**一次请求都不发** |
| 长时间后台 | `WorkManager` 周期任务 | 15 分钟一次，`NetworkType.CONNECTED`，由系统在维护窗口里批量调度 |
| 省电模式 / Doze | 前台轮询自动放慢 | 间隔下限拉到 60 秒，标题栏会显示"省电模式：已放慢到 N 秒" |

小组件的刷新不是自己转的：`WorkManager` 那次刷新顺带更新它，`updatePeriodMillis` 只作为系统兜底。而且只在**汇总内容真的变了**时才 `updateAll`（用 `distinctUntilChanged` 比内容、忽略 `updatedAt`），否则每 5 秒叫醒一次 launcher 只为了重画一个没变的数字。

## 性能上改掉的几处

1. **`CookieJar` 每个响应都在写盘。** hub 绝大多数响应不带 `Set-Cookie`，而原来的实现无论列表空不空都调 `persist()` → 每次轮询一次 `SharedPreferences` 写入加 fsync。现在空列表直接返回，且只在值真的变了才写。
2. **管理员那三个请求改成并发。** `/api/version`、`/api/db`、`/api/settings` 原本串行，是三个往返延迟；现在 `async` 一起发。（不能用 `awaitAll`——三种不同载荷类型会被收敛成公共父类，结果就丢了。）
3. **头部聚合值不再按属性算。** 原来 `state.online` / `totalNetRx` 之类是计算属性，每次重组都会重新遍历节点列表；现在折进一个 `Rollup`，每个 state 只算一次。
4. **历史请求加了 30 秒 TTL 缓存。** hub 对历史查询有并发闸门（一次只放 4 个），反复打开同一个节点不该去占名额。
5. **小组件的 `Json` 实例提到文件级**，不再每次读取都新建。

## 关于接口

客户端只用 hub 已有的 HTTP 接口，没有为它加任何服务端改动：

| 用途 | 接口 | 鉴权 |
|---|---|---|
| 实时节点帧 | `GET /api/nodes` → `{nodes, admin}` | 公开页开启时可匿名 |
| 主控版本 | `GET /api/version` → `{hub, hub_latest, agent_latest, notice}` | 管理员 |
| 数据库状态 | `GET /api/db` → `{path, size, wal, free, oldest, oldest_ago, retention, rows}` | 管理员 |
| 主控设置 | `GET /api/settings` | 管理员 |
| 节点历史 | `GET /api/nodes/{id}/metrics?hours=&points=` → `{metrics, ping, probes, loss, step}` | 该节点公开时或已登录 |
| 登录 | `POST /api/auth/login` `{"password": "…"}` | — |

历史那一项每个数组里一行的形状（`ping` 的字段是 hub 侧 `close_bucket` 定死的，很值得记）：

```jsonc
// metrics 里一行
{ "ts":…, "cpu":…, "mem_used":…, "disk_used":…, "net_rx":…, "net_tx":…,
  "net_rx_max":…, "net_tx_max":…, "cpu_max":…, "minutes":…,
  "swap_used":…, "tcp":…, "udp":…, "procs":… }

// ping 里一行；latency 是该桶中位数，没有应答时缺省
{ "task_id":1, "ts":…, "latency":37, "band":[31,52], "loss":2 }
//   band 只在桶内真的有波动时才给（小时/六小时窗口一桶一个采样，给了也是零高度的带）
//   loss 只在桶内真丢了包时才给，是整数百分比
// probes: {"1":"上海"}   loss: {"1":0.14}   step: 60
```

**主控版本、数据库和设置这三个接口在 hub 侧是 `Admin` 提取器**，也就是必须登录。所以 app 不登录时显示节点列表（前提是主控开了公开页），登录后才补齐主控自身的版本与存储信息 —— 首屏那张卡上会明说"登录后可查看主控版本、数据库与设置"。

hub 的会话是 `HttpOnly` cookie。那只是对浏览器的约束，OkHttp 有自己的 CookieJar，所以 app 把 `Set-Cookie` 原样存下来复用，和浏览器标签页是同一个机制。

**没有用 WebSocket。** hub 每 2 秒往 `/api/ws` 推一帧，但一个大部分时间在后台的手机为此要不断拆建连接；按用户选的间隔轮询更省电，也不会出现"看着还连着其实早就断了"的静默过期 —— 那正是面板自己要装看门狗去防的故障。

## 构建

需要 JDK 17、Android SDK（platform 35 + build-tools 35.0.0）。仓库自带 Gradle wrapper：

```bash
./gradlew :app:assembleDebug        # app/build/outputs/apk/debug/app-debug.apk
./gradlew :app:assembleRelease      # 未签名；R8 混淆 + 资源压缩，18.4 MB -> 2 MB
```

`local.properties` 里的 `sdk.dir` 要指向你自己的 SDK。

**已验证**（2026-10-16，Gradle 8.9 / JDK 17 / AGP 8.7.3）：`assembleDebug` 与 `assembleRelease` 均 BUILD SUCCESSFUL；release 走完 R8 与资源压缩无 Missing class；产物内可见 `res/xml/hub_widget_info.xml`。已在真机上运行验证。

| | |
|---|---|
| Kotlin | 2.0.21 |
| AGP / Gradle | 8.7.3 / 8.9 |
| compileSdk / minSdk / targetSdk | 35 / 26 / 35 |
| Compose BOM | 2024.12.01（Material 3） |
| Glance | 1.1.1 |
| WorkManager | 2.10.0 |
| 网络 | OkHttp 4.12 + kotlinx.serialization |

minSdk 26 是 `Glance` 的下限。动态取色本身需要 API 31+，31 以下自动回落到 Material 3 的基线配色 —— 功能不受影响，只是不跟壁纸。

小组件用的是 Glance 核心包里的 `androidx.glance.GlanceTheme`（不是 `glance-material3`）：它在 Android 12+ 上自己就解析到 `DynamicThemeColorProviders`，也就是壁纸调色板，和 app 的 `dynamicLight/DarkColorScheme` 同源。因此不需要额外依赖，也不需要为 API 31 以下写分支。

Glance 1.1.1 的两个 API 坑，踩过记下来：`actionStartActivity` **只有接受 `Intent` 的重载**，没有 `actionStartActivity<T>()`；`defaultWeight()` 是 `RowScope` 的成员扩展，不需要也不能 import。

## 结构

```
app/src/main/java/dev/monitorprobe/client/
├── MonitorApp.kt              持有唯一的 repository；不轮询，只把汇总推给小组件
├── MainActivity.kt            单 Activity；轮询循环跟着界面生命周期起停；节点选择
├── data/
│   ├── Models.kt              Node / Metrics / History / MetricPoint / PingPoint / HubSummary…
│   ├── Prefs.kt               地址、间隔、会话 cookie、小组件缓存
│   ├── HubApi.kt              OkHttp + 持久 CookieJar（只在 cookie 真变了才写盘）
│   └── HubRepository.kt       刷新、并发的管理员请求、历史 TTL 缓存、省电间隔
├── work/RefreshWorker.kt      15 分钟一次的 WorkManager 周期刷新
├── ui/
│   ├── theme/Theme.kt         MonitorTheme：dynamicLight/DarkColorScheme
│   ├── HubScreen.kt           主控信息卡 + 分组筛选 + 列表 + 三个对话框
│   ├── Grouping.kt            分组筛选与分节（沿用面板的 all / none / =组名 编码）
│   ├── NodeCard.kt            单台节点
│   ├── NodeDetail.kt          延迟监控 + 资源历史
│   ├── Charts.kt              Canvas 折线 / 区间带 / sparkline
│   └── Components.kt          MeterRow / StatusDot / KeyValue
├── format/Format.kt           字节、速率、时长、国旗、计费周期
└── widget/HubWidget.kt        Glance 小组件 + 刷新回调
```

`data/Models.kt` 里的字段名和 hub 的 JSON 一一对应（`@SerialName`），默认值给全了，所以 hub 比 app 新或旧都不会解析失败。
